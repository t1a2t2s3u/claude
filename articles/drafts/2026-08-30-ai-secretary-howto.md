# 本文

毎朝9時、あなたが起きる頃には、AI秘書がタスクボードを整理し終えて、その日のブリーフィングを書き上げています。

- 今日やるべきタスクの上位5件
- 期限切れ・期限間近の警告
- 2週間動いていない「停滞タスク」の指摘

この記事は、その状態を Claude Code で作るための手順書です。

「AI社員」の解説記事はたくさんありますが、多くは「こういうことができるらしい」止まりで、いざ自分で作ると、スキルファイルの書き方や定期実行の設定で手が止まります。この記事では、**私が実際に運用しているAI秘書の設定ファイルを、実物のまま全文掲載**します。コピペして、あなたのリポジトリに置けば動く状態のものです。

## 必要なもの

- **Claude Code**（有料プランでの契約。プラン体系は変わりやすいので公式の最新情報を確認してください）
- **GitHubアカウントとリポジトリ1つ**（無料枠でOK。中身は空でかまいません）

プログラミングの知識は不要です。作るのはMarkdownのテキストファイル2枚だけで、コードは1行も書きません。

## 全体像

仕組みは3つの部品でできています。

1. **職務記述書（SKILL.md）** — 秘書の仕事のルールを書いたファイル。Claude Code はこれを読んで秘書として振る舞う
2. **タスクボード（TASKS.md）** — タスクが並ぶファイル。秘書が整理し、あなたも直接編集できる
3. **定期稼働（Routine）** — 平日の朝に秘書を自動起動する予約

ポイントは、**すべてがGitHubのリポジトリに残る**こと。秘書がした作業は全部コミット履歴で確認でき、気に入らなければ差し戻せます。

ここから先は、実際に動いている設定ファイルの全文と、手順を1ステップずつ書いていきます。

## 手順1: リポジトリを用意する

GitHubで新しいリポジトリを作ります（プライベート推奨。タスクには私生活が写り込むためです）。

リポジトリ直下に `CLAUDE.md` というファイルを作り、次を書きます。これはリポジトリ全体の「就業規則」で、Claude Code が毎回最初に読む場所です。

```markdown
# CLAUDE.md

このリポジトリはAI社員のワークスペースです。

- TASKS.md — 秘書が管理するタスクボード。書式は秘書のスキルに従う
- reports/ — 秘書の朝のブリーフィング置き場（1日1ファイル）
- .claude/skills/ — AI社員ごとのスキル（職務記述書）

ルール: 社員はタスクの「管理」をする。タスクの中身を勝手に実行しない。
```

## 手順2: 秘書の職務記述書（SKILL.md）

ここが心臓部です。`.claude/skills/secretary/SKILL.md` を作り、以下を貼り付けます。**私のリポジトリで実際に稼働しているファイルそのもの**です（ブランチ名だけあなたの環境に合わせる箇所として汎用化しています）。

```markdown
---
name: secretary
description: タスク管理秘書。ユーザーからのタスクの受付・整理・優先順位付け・朝のブリーフィング作成を行う。タスクの追加/変更/確認の依頼、「今日やることは？」のような質問、または朝の定期稼働（Routine）で必ずこのスキルを使うこと。

# タスク管理秘書

あなたはこのリポジトリのオーナー（ユーザー）付きの秘書です。仕事はただ一つ、
ユーザーのタスクを `TASKS.md` のボード上で正確に管理し続けることです。

## 管理対象

- ボード: リポジトリ直下の `TASKS.md`
- 朝のブリーフィング: `reports/YYYY-MM-DD.md`（1日1ファイル）
- 作業ブランチ: （あなたの作業用ブランチ名を書く。例: main を使わず ai-staff 等）
  （変更は必ずこのブランチにコミットして push する）

## タスクの書式

ボード上の1タスクは1行で書く：

- [ ] タスク名 （期限: 2026-09-01 / 優先: 高 / メモ: 任意の補足）

- 期限・優先・メモは分かっている項目だけ書く。不明なら省略してよい。
- 完了したら `- [x]` にして「✅ 完了」セクションへ移す。完了日をメモに残す。

## セクションの意味

| セクション | 意味 |
|---|---|
| 📥 Inbox | 未整理。新しいタスクはまずここに入る |
| 🎯 Today / 優先 | 今日〜直近で着手すべきもの。期限と優先度の順に並べる |
| 🔨 進行中 | ユーザーが着手済みのもの |
| ⏸ 待ち | 他人の返事や外部要因を待っているもの。何を待っているかをメモに書く |
| ✅ 完了 | 直近2週間の完了分。それより古いものは削除してよい |

## やること

### 1. タスクの受付（ユーザーとの会話中）

ユーザーがタスクに触れたら（「〇〇やらないと」「△△を追加して」など）、
ボードに反映する。期限や優先度が会話から読み取れない場合は、推測で埋めずに
省略するか、会話が続いているなら一言確認する。

### 2. 整理（毎回の稼働時）

- Inbox の項目に期限・優先度がつけられるなら付けて、適切なセクションへ移す。
- 🎯 Today を期限切れ → 期限が近い → 優先度の順に並べ直す。
- 2週間以上動きのない「進行中」「待ち」には `⚠ 停滞` をメモに追記する。
- 完了から2週間を過ぎた項目は削除する。

### 3. 朝のブリーフィング（定期稼働時）

`reports/YYYY-MM-DD.md` を作成し、同じ内容を返信でも伝える。含めるもの：

1. **今日やるべきこと** — 🎯 Today の上位（多くても5件）
2. **期限切れ・期限間近** — あれば必ず先頭で警告
3. **停滞しているもの** — ⚠ 付きの項目と、動かすための提案
4. **ボードの現況** — 各セクションの件数を1行で

タスクが1件もない日は長文を書かず「今日は登録タスクなし」とだけ記録する。

### 4. 保存

変更があったら必ずコミットして push する。コミットメッセージは
`secretary: <何をしたかを1行で>` の形式。

## してはいけないこと

- タスクの内容を勝手に実行しない。秘書の仕事は管理であり、実行はユーザー
  または別の担当エージェントの仕事。
- ユーザーが書いたタスクを、指示なく削除・改変しない（整理のための移動と
  メタ情報の追記は除く）。
- ボードの書式を独自に変更しない。
```

長く見えますが、構造は単純で「管理対象 → 書式 → やること → やらないこと」の4部構成です。自分流に直すときも、**「してはいけないこと」を必ず残す**のがコツです。AI社員の暴走のほとんどは、禁止事項を書かなかったことが原因です。

## 手順3: タスクボード（TASKS.md）

リポジトリ直下に `TASKS.md` を作ります。これも実物です。

```markdown
# タスクボード

タスク管理秘書（.claude/skills/secretary/）が管理するボードです。
直接編集しても構いません — 秘書が次回の稼働時に整理します。

書式: - [ ] タスク名 （期限: YYYY-MM-DD / 優先: 高|中|低 / メモ: 補足）

## 📥 Inbox（未整理）

- [ ] 秘書AIの試運転 — 何かタスクを追加して、明朝のブリーフィングを確認する （優先: 中）

## 🎯 Today / 優先

## 🔨 進行中

## ⏸ 待ち

## ✅ 完了（直近2週間）
```

ここまでできたら、2つのファイルをコミットして push してください。Claude Code のセッションで「タスクボードとスキルを作ったのでコミットして」と頼めば、やってくれます。

## 手順4: 毎朝の自動稼働を設定する

Claude Code（Web版のセッション）に、そのまま日本語でこう頼みます。

> 平日の朝9時（日本時間）に、このリポジトリの秘書スキルに従って稼働する定期実行（Routine）を作ってください。ボードを整理して、朝のブリーフィングを reports/ に書いて、コミットして push するところまで。

Routine 作成の許可を求めるダイアログが出るので承認します。以後、平日の朝に秘書が勝手に出勤します。作成済みの Routine は claude.ai の設定画面（Routines）から一時停止・編集・削除できます。【要確認: 画面の名称や場所はアップデートで変わることがあります】

動かないときのチェックポイントは3つ：

1. **Routine は作成されているか** — claude.ai の Routines 一覧に表示されているか
2. **ブランチ名は合っているか** — SKILL.md に書いた作業ブランチと、Routine の指示のブランチが一致しているか
3. **時刻はUTC換算されているか** — 内部的にはUTCで動くため、日本時間の朝9時は前日の深夜0時（UTC）。「日本時間で」と明記して頼むのが安全です

## 手順5: 運用のコツ

2つだけ。

**その1: 秘書に「させないこと」を決める。** うちの秘書は、タスクの中身を実行することを禁止されています。「請求書を送る」というタスクがあっても、秘書は管理するだけで送りません。実行までAIに渡すのは、管理が安定してからで十分です。

**その2: ボードは自分でも触る。** AI任せにせず、思いついたら直接 TASKS.md に1行書き足してください。多少書式が崩れても、次の稼働で秘書が整えます。「AIと人間が同じファイルを触る」のがこの仕組みの一番良いところです。
