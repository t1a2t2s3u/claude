# 本文

AI社員チームの運用日記、第2回です。第1回（【第1回のURL】）では、プログラミング未経験の私が Claude Code に最初の社員として「秘書」を雇った話を書きました。

解説記事だとこのあとは「毎朝ブリーフィングが届くようになりました。快適です」で終わるところです。でも、実際に起きたことは違いました。今回は、**雇ったはずの秘書が10日あまり一度も成果物を納品しなかった**という失敗と、そこからの立て直しの記録です。

AI社員の成功例はたくさん流れてきますが、「動かなかったとき何が起きるのか」を書いた一次情報はほとんど見かけません。これから試す人が同じ場所でつまずかないように、そのまま書きます。

## 失敗編: 秘書を「雇った」のに、何も届かない

秘書を雇ったのは8月26日でした。職務記述書を用意して、平日の朝に自動で動く予約も入れて、仕組みとしては完成したつもりでした。

ところが、報告書が置かれるはずのフォルダは、その後もずっと空のままでした。あとから分かった原因は、秘書のAI自体の能力ではなく、**権限の設定**です。秘書は毎朝ちゃんと起動して仕事をしようとしていたのに、成果物を「オフィス」（共有の保管場所）に提出する権限がなく、書いたものを納品できないまま終わっていたのです。

人間の会社でいえば、初日から真面目に出社していたのに、オフィスの鍵を渡されていなくて、書いた書類を毎日持ち帰って捨てていたようなものです。働いていないのではなく、**働いた結果が私に届く経路がなかった**。これは仕組みを用意した私の側の失敗でした。

【あなたの体験をここに: 何も届かなかった10日間、実際どうしていたかを正直に。忙しくて放置していた・そもそも気づいていなかった、など実際のところを1〜2文】

ここで得た学びは単純で、**AI社員は「雇って終わり」ではない**ということです。初日に「成果物が実際に自分の手元に届くところまで」を1回確認する。これをサボると、動いていないことにすら気づけません。

## 立て直し編: 「専用の作業部屋」を用意したら動いた

原因が分かってからやった立て直しは、大げさなものではありません。秘書に**専用の作業部屋を1つ用意して、毎朝決まった時間にそこへ声をかける方式**に変えました。毎回まっさらな環境で働かせるのをやめて、納品の経路まで整えた部屋に常駐してもらうイメージです。

技術的な細部は省きますが（第1回同様、全部日本語のチャットで頼んで設定してもらいました）、効果は翌朝すぐに出ました。9月6日の朝、初めてのブリーフィングがフォルダに置かれていたのです。今日やるべきタスクの上位、期限切れの警告、タスクボードの現況——注文していたものが、注文どおりの形で届いていました。

【あなたの体験をここに: 初めてブリーフィングが届いた朝の率直な感想。拍子抜けした・じわじわ嬉しかった、など1〜2文】

## いまのチームの様子

秘書が動き出したのと前後して、チームは一気に増えました。現在は秘書に加えて、note記事を担当する編集長・リサーチャー・ライター・校閲・SNS担当・アナリストがいます。編集長が企画を立て、ライターが決まった曜日に下書きを書き、気づけば記事の下書きが4本たまっていました。

ただ、正直な現状も書いておきます。**下書きは4本あるのに、公開できた記事はまだ0本です。** AI側は淡々と納品してくるのに、最後の仕上げと投稿ボタンを担当する人間（私）が追いついていない。いまこのチームのボトルネックは、明らかにAIではなく私です。

AIの活用が「使う」から「任せる」へ進むと、人間の仕事は作業から**判断と検品**に変わります。そして任せた側の処理能力が、今度は上限になる。運用して初めて実感した、想像していなかった種類の課題です。

## 次回予告

次回は、たまった下書きをいよいよ世に出します。初投稿がどうなったか、数字も含めて報告する予定です。チームの立ち上げ方や指示書の書き方は、別途手順書の記事にもまとめていきます。
