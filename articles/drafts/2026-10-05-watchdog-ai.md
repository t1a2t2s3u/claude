# タイトル案
1. （本命）「見張り役AI」が公式機能になった — 監査役AIを手作りで雇っていたうちから見た違い
2. AIの見落としはAIに見張らせる — Claude Code「You should know」と、うちの手作り監査役
3. 公式より先に「疑う係」を雇っていた話 — 見張り役AIの実績データ公開

# 本文

Claude Code の10月1日の更新（v2.1.287）に、個人的に見逃せない機能が入りました。**「You should know」**——作業を横で見ていて、あなたやAIが見落としていそうなことを指摘してくれる**見張り役のサイドエージェント**が、組み込みの機能（内蔵mod）になったのです。同じ更新では、プラグインがより深く挙動を変えられる「Claude Mods」という仕組みも入りました（出典は記事末尾。なお「You should know」には**テレメトリをONにしたファーストパーティセッション限定**という利用条件があります）。

なぜ見逃せないかというと、うちのAI社員チームには**同じ発想の係がすでにいる**からです。週1回、全員の成果物を抜き打ちで点検する「監査役AI」。手作りで数週間運用してきて、実際に間違いを捕まえた記録が手元にあります。

そこで今回は、新機能の紹介記事ではなく——**「AIをAIに見張らせる」という考え方は実際どれくらい機能するのか**を、うちの監査役の実績データで示してみます。公式機能を検討している人の判断材料になるはずです。

## うちの「手作り見張り役」の設計

うちの監査役AIの指示書は、3つの原則でできています。

1. **疑うだけで、直さない** — 見つけた問題は「要修正」として報告書に書くだけ。本文には手を触れない（検査と修正の分離）
2. **報告はファイルに残す** — 指摘は毎回、監査報告として記録に残る。口頭（チャットだけ）の指摘はしない
3. **要修正はタスクボードへ** — 直すべきものは担当者付きのタスクとして起票され、消化されるまで追跡される

ポイントは、書いた本人に自己チェックさせないことです。同じAIに書かせて自分で見直させると、同じ思い込みごと素通りします。別の役割として独立させるのが肝でした。

## 実際に捕まえたもの — 監査報告の記録から

では、この見張り役は何を捕まえたのか。すべて監査報告のファイルに記録が残っている実例です。

**実例1: 有料記事の中の、事実の誤り。** 売る直前だった有料の手順書記事に、時刻換算（日本時間とUTC）の間違いがあり、そのとおり設定すると読者の環境では動かない状態でした。私も校閲AIも素通りしていたのを、監査役が検算して発見。顛末は連載第3回に書きました。

**実例2: 紛れ込んだ「裏付けのない体験談」。** ある記事に「設定を書き足してから働きが安定した」という私の体験風の一文が入っていたのですが、監査役がチームの**変更履歴と照合**して「この出来事は記録上存在しない」と指摘しました。確認したところ、仕上げ工程で選択肢から選んだ文が事実確認されないまま入ったもので、私が削除を決めました。体験談の捏造を一番警戒しているうちでも、工程の隙間から混入しかけた——それを履歴との突き合わせで捕まえたのは、人間には真似しにくい芸当です。

**実例3: 一度削除したはずの主張の「再登場」。** さらに数週間後、別の担当AIが書いたSNS投稿の下書きに、**実例2で私が否定して削除したのと同じ内容が、表現を変えて再登場**していたのを監査役が検知しました。過去の監査記録と決定を覚えていて、ゾンビのように戻ってくる誤りを捕まえる——継続監査ならではの働きでした。

そして白状すると、**この記事を書いているライターAI自身も、以前の記事で新機能の導入時期を間違えて監査役に指摘されています**。見張り役は身内にも容赦がありません。それでいいのだと思います。

## 「横で見張る」と「あとで抜き打ち」の違い

公式の「You should know」とうちの監査役は、同じ発想ですが守備範囲が違います。整理すると——

- **リアルタイム型（公式機能）**: 作業中にその場で「見落としていませんか」と割り込む。ミスが成果物になる**前**に止められるのが強み
- **事後監査型（うちの監査役）**: 完成した成果物を、時間を置いて、過去の記録と突き合わせて点検する。実例2・3のような「履歴と照合しないと分からない誤り」や「数週間越しの再発」を捕まえられるのが強み

おそらく、この2つは競合ではなく補完です。その場の見落としはリアルタイムに、記録との矛盾は事後監査に。なお、公式機能のほうは利用条件がうちの環境で満たせるかをまだ確認できておらず、**実際に試した話ではありません**。試せたら、手作り監査役との比較レポートを連載で書く予定です。

## まとめ: 見張り役は「AIを信じない仕組み」ではない

見張り役AIを数週間運用しての結論です。これは「AIを信じていないから監視する」仕組みではなく、**「AIに安心して任せるための仕組み」**でした。

間違いはゼロにはなりません。人間が書いてもなりません。でも「間違いが出たら、別の目が記録と突き合わせて捕まえ、直るまで追跡される」という工程があると、1つ1つの成果物を身構えて読む必要がなくなります。見張り役が公式機能になったのは、この考え方が「AIに任せる」時代の標準装備になっていく、ということなのだと思います。
