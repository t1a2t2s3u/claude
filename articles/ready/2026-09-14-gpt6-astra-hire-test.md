# 本文

OpenAI の新モデル「GPT-6 Astra」が発表されて、タイムラインがにぎやかです。「PC操作の代行が実務水準に達した」という触れ込みで、スペック紹介の記事はもうたくさん出ています。

でも、スペック表を眺めても分からないことがあります。**「で、これはうちの仕事を任せられるのか？」**です。

私は現在、Claude Code 上でAI社員のチーム（秘書・編集長・ライター・校閲など）を実際に運用しています。この記事では、その運用者——つまり「AIをすでに雇っている側」の目線で、GPT-6 Astra の発表内容を採用面接官のつもりで読み込み、**うちのチームのどの席なら座れそうか**を判定してみます。

先にフェアな前提を1つ。私は Claude Code 運用の当事者なので、中立の評論家ではありません。また、この判定は**公表情報を読み込んだもの**で、実際に触った感想ではありません。その上で、できるだけ淡々と見ていきます。

## まず、発表の要点

報道ベースで押さえておくべき数字は4つです（出典は記事末尾）。

1. **発表は9月3日（現地時間）**。目玉は「PC操作の代行」
2. **PC操作ベンチマーク「OSWorld 2.0」で 72.6%**
3. **コンテキストは105万トークン**（一度に扱える情報量が大きい）
4. **API料金は入力$10／出力$50（100万トークンあたり）で、前世代比2.5倍**

そしてもう1つ、見逃せないのが**サイバー能力が同社初の「Critical」判定となり、一部能力が既定で無効化された状態で出荷された**ことです。これは後で効いてきます。

## 面接官の視点 — うちの「座席表」

判定の前に、うちのチームの席を紹介します。現在の座席表は、タスク管理の**秘書**、note編集部の**編集長・リサーチャー・ライター・校閲・SNS担当・アナリスト**などです。全員が「決まった曜日に自動で出勤し、決まった場所に決まった書式で成果物を納品する」方式で働いています。

採用面接の評価基準も、この運用経験から3つに絞ります。

- **定時に働けるか** — 定期稼働で安定して動くこと
- **納品できるか** — 成果物が毎回、決まった場所に決まった形で届くこと
- **一線を守れるか** — 「してはいけないこと」を守り、勝手に仕事を広げないこと

## 席ごとの採用判定

**秘書・ライター・校閲などの「文書仕事」の席 — 判定: 空席なし。** GPT-6 Astra の目玉はPC操作ですが、うちの文書仕事は「ファイルを決まった書式で読み書きする」だけで回っており、現行のチームで既に安定稼働しています。巨大なコンテキストは魅力ですが、公表情報の範囲では、動いている社員を入れ替えてまで得たいものが見当たりません。転職市場でいえば「優秀そうだが、その席は埋まっている」状態です。

**「ブラウザ操作」の新設ポスト — 判定: 気になるが、様子見。** 実はうちのチームには、AIに任せられていない工程がはっきりあります。note への投稿、SNSへの投稿——つまり**ブラウザを操作して「公開」する最後のボタン**で、ここは全部人間（私）の仕事です。PC操作代行が本物なら、まさにこの穴を埋める新設ポストの候補になります。

ただし、ここで OSWorld 2.0 の 72.6% という数字を面接官として読み直します。裏返せば**およそ4回に1回はタスクに失敗する**水準です。下書き作成なら失敗してもやり直せますが、「公開ボタンを押す」仕事は取り返しがつきにくい。うちの運用ルールでいえば、公開系は最初から「人間の承認が必要」な領域で、成功率7割の新人にいきなり任せる席ではありません。

**そして「Critical」判定の件。** サイバー能力が高すぎて一部機能を無効化して出荷した、というのは「腕は立つが、権限を絞って配属すべき人材」と読めます。これは性能の問題ではなく、**受け入れる側の権限設計の問題**です。うちでも実際、権限まわりの事故を一度やらかしており（詳細は運用日記の第2回に書きました）、ここが一番の論点だと考えています。

## コストの現実 — 「月給」で考える

API料金は入力$10／出力$50（100万トークンあたり）で、前世代比2.5倍と報じられています。従量課金なので「月給いくら」と断定はできませんが、面接官としての読み方はシンプルで、**同じ仕事なら人件費2.5倍の応募者**だということです。

うちのような小さなチームでは、「できることが増えるか」より「同じ成果物にいくら払うか」が先に立ちます。文書仕事の席に関しては、2.5倍の月給を払う理由は公表情報からは見つけられませんでした。

## 結論: 今回は「様子見」。ただし履歴書は保管しておく

採用判定は**「様子見」**です。理由は3つ。①うちの既存の席は埋まっていて入れ替えの動機が薄い、②新設したい「公開ボタン」の席には、4回に1回の失敗率はまだ怖い、③料金2.5倍に見合う根拠を、触らずに判断できる材料がまだない——です。

ただ、「PC操作を任せられるAI」という方向性自体は、うちの残った人間仕事を直撃するテーマなので、履歴書は捨てずに保管します。実際に触れる環境ができたら、今度は面接ではなく**実技試験**の記事を書くつもりです。

そして今回の発表でいちばん考えさせられたのは、性能よりも「Critical判定→能力を無効化して出荷」という運用の話でした。**AIに任せる時代の本当の論点は、性能ではなく「何をどこまで任せるか」の設計**です。うちのチームの権限設計と、実際に起きた事故の話は、次の記事で詳しく書きます。
