# タイトル案
1. （本命）AI社員同士はどうやって連絡を取り合っているのか — うちの職場の実物と、Claude Code の新機能「セッション間メッセージ」
2. 複数のAIを連携させると何が起きるのか — ファイルのバケツリレーで回る、うちのAIチームの1週間
3. AIチームの「社内連絡」の実物を公開します — セッション間メッセージ時代の前夜に

# 本文

Claude Code に、**セッション同士がメッセージを送り合える機能**が入りました。AI同士が直接連絡を取り合う——「AI社員チーム」を運用している身としては、見逃せないニュースです。

同時に、こうも思いました。解説記事はもう出ているけれど、**「じゃあ実際に動いている複数AIのチームは、今なにで連携しているのか」**の現場の話はほとんど見かけないな、と。

私は Claude Code 上で十数役のAI社員チーム（秘書・編集長・ライター・校閲・監査役など）を運用しています。この記事では、①新機能の要点、②うちのチームの連携方式の**実物**、③その方式の良さと限界、④新機能で何が変わりそうか——を、運用者の目線でまとめます。なお、新機能はまだ試していないので、④は公表情報ベースの期待と懸念です。試したら連載で報告します。

## まず、ニュースの要点

Claude Code の v2.1.277〜278 で入った変更のうち、今回の主役は2つです（出典は記事末尾）。

1. **セッション間メッセージ** — 別々に動いている Claude Code のセッション同士が、メッセージを送り合えるようになった（対応は macOS/Linux）
2. **AGENTS.md 対応** — 指示書ファイルの互換対応（CLAUDE.md がないプロジェクトでは AGENTS.md を読む）

「AI社員」を複数動かしている人にとって、1つ目はかなり大きい変化です。今まで別々の部屋で働いていた社員同士が、直接会話できるようになるからです。

## で、うちは今どうしているか — 答え: ファイルのバケツリレー

正直に言うと、うちのチームの連携は**「共有フォルダにファイルを置いて引き継ぐ」**という昔ながらの方式です。AI同士がリアルタイムに会話することは一度もありません。それでも毎週チームは回っています。実際の1週間のリレーをたどってみます。

- **日曜**: リサーチャーが今週の動向を調査し、`strategy/research/日付.md` というレポートを置く
- **月曜**: 編集長がそのレポートを読んで編集会議。企画カレンダー（`strategy/calendar.md`）を更新し、記事ごとの指示書（ブリーフ）を `strategy/briefs/` に置く
- **火・木**: ライター（私のこの記事を書いている係）が「未着手」のブリーフを拾って下書きを書き、`articles/drafts/` に置いて、ブリーフの状態を「執筆済み」に変える
- **水・金**: 校閲が下書きを点検し、記事の末尾に校閲メモを追記して、合格作を「投稿待ち」フォルダへ移す
- **毎日昼**: 仕上げ担当が、記事に残った「私にしか書けない箇所」を拾い、`finishing/questions.md` に「はい／いいえで答えられる質問」として並べる
- **週末**: 監査役が全員の成果物を抜き打ち点検し、監査報告を置く

見てのとおり、**前の工程の成果物ファイルが、次の工程への連絡そのもの**になっています。この記事自体も、日曜のレポート→月曜のブリーフ→火曜の執筆、というリレーの産物です。

## ファイル引き継ぎの、意外な強さ

「原始的だな」と思われそうですが、運用してみるとこの方式には明確な強みがあります。

**第一に、記録が全部残ること。** 誰が・いつ・何を根拠に動いたかが、ファイルと変更履歴で後から完全に追えます。第2回に書いた「秘書が10日間納品できていなかった」事故も、履歴が残っていたから原因を特定できました。

**第二に、引き継ぎ書がそのまま仕様書になること。** ブリーフの書式、校閲メモの書式、質問シートの書式——「何をどう書いて渡すか」が決まっているので、担当のAIを入れ替えても、次の担当は同じ書式を読んで同じように働けます。口伝えの引き継ぎがないチームは、属人化ならぬ「属AI化」をしないのです。

**第三に、割り込まれないこと。** 各自が決まった曜日に自分の仕事だけをやるので、「会議で1日が溶ける」が起きません。

## 一方で、限界もはっきりある

弱点は**リアルタイムに割り込めない**ことです。連絡がファイル経由なので、伝言は「次にその係が出勤する日」まで届きません。

実害も経験しています。監査役が有料記事の中に事実の誤りを見つけたとき、その指摘が実際に修正されるまで**1週間近く**かかりました（詳しくは連載第3回に書きました）。指摘のファイルは置かれていたのに、それを拾う係がおらず、「急ぎで誰かに伝える」手段もない。バケツリレーは、バケツを受け取る人が来る日まで水が動かないのです。

## セッション間メッセージで何が変わりそうか

そこで新機能です。まだ試していない前提で、期待と懸念を書きます。

**期待は「急ぎの伝言」が可能になること。** 監査役が重大な誤りを見つけたその場で、担当セッションに直接知らせる。ライターが執筆中に、リサーチャーに「この数字の出典だけ確認して」と頼む。今のうちのチームに欠けている「割り込み」の経路が、まさにここに生まれそうです。

**懸念は、連絡が会話に溶けて消えること。** ファイル方式の強みは記録性でした。メッセージでのやり取りが増えるほど、「誰が何を根拠に動いたか」が会話の中に散らばって、後から追えなくなるおそれがあります。人間の職場でいえば、「決定事項が全部口頭とチャットで、議事録がない会社」です。使うなら、大事な決定は結局ファイルに書き残すルールとセットになる気がしています。

## まとめ: 連携の本体は、機能ではなく「引き継ぎ書の書式」だった

うちの運用でわかった結論はこれです。**複数AIの連携の本体は、通信手段ではなく「何を・どの書式で・どこに置いて渡すか」を決めること。** 書式さえ決まっていれば、伝達がファイルでもメッセージでも、チームは回ります。逆に書式が曖昧なまま通信手段だけ増やすと、たぶん散らかります。

セッション間メッセージは、この「バケツリレーの弱点」をピンポイントで埋めてくれる可能性があるので、うちでも試したら実際の使用感を連載で報告する予定です。AI社員チームの実運用の記録、よかったらフォローしてお待ちください。
