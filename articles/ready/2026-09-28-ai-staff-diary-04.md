# 本文

AI社員チームの運用日記、第4回です。今回は、この連載の「舞台」そのものに関わるニュースから始めます。

9月23日、Claude Code の**クラウドセッション**が研究プレビューを卒業して、**正式提供**になりました（出典は記事末尾）。クラウドセッションというのは、ざっくり言うと「自分のパソコンの中ではなく、クラウド上に置かれた作業部屋で Claude Code が働く仕組み」です。部屋はネットの向こうに常にあるので、決まった時刻に自動で仕事を始める「定期稼働」と組み合わせられます。

正式提供になったことで、これから「定期的に動くAI」を始める人が増えるはずです。そこで今回は、機能紹介ではなく——**正式提供の前から、この環境で13人のAIチームを毎日回してきた住人の実録**を書きます。「導入したら実際どうなるのか」の先回りです。

## 種明かし: この連載のAI社員たちは、ずっとそこに住んでいた

実はこの連載に出てくるAI社員たち——秘書も、編集長も、この記事を書いているライターも——全員が、まさにこのクラウドセッション＋定期稼働の組み合わせで動いています。

1週間の実際の回り方はこうです。

- **平日の毎朝**: 秘書が起動して、タスクボードを整理し、朝のブリーフィングを置く
- **日曜**: リサーチャーが今週の動向を調べてレポートを置く
- **月曜朝**: 編集長がそのレポートを読んで編集会議。今週の記事の指示書を書く
- **火・木**: ライターが指示書を拾って下書きを書く（今まさにこれ）
- **水・金**: 校閲が下書きを点検する。週末には監査役が全部署を抜き打ち点検する

私がこの間なにをしているかというと、基本的には何も。届いた成果物を読んで、質問に答えて、公開するかを決めるだけです。

正直な感想を一言でいえば、「Claude、すごい」です。

## プレビュー期間に、実際に困ったこと

いいことばかり書くと宣伝になってしまうので、この環境で実際に起きた困りごとも書きます。連載の読者にはおなじみの話です。

**いちばんの事故は、立ち上げ直後の秘書が権限の問題で一度も納品できなかった件**（第2回・【第2回のURL】）。クラウドの作業部屋で毎朝ちゃんと働いていたのに、成果物を共有の置き場に提出する権限がなく、10日あまり空振りしていました。「クラウドで自動で動く」は、**動くことと、成果が自分に届くことが別問題**なのだと、初っ端に学びました。

もう1つは、第3回（【第3回のURL】）に書いた「監査役の指摘が1週間近く放置された」件。これは環境のせいではなく、うちの手順の穴でしたが、**全員が自動で動く職場では、誰の担当でもない仕事は本当に誰もやらない**という教訓は、この方式を使う人みんなに関係すると思います。

どちらも共通するのは、事故が「静かに」起きることです。クラウドの職場にはエラー音も舌打ちも聞こえません。だからこそ、毎朝の報告書と週次の監査のような「異常が翌朝見える仕組み」をセットにしてから、安心して放置できるようになりました。

## 「職場がクラウドにある」ことの、実際の意味

1か月あまり住んでみて感じる、この方式の本質は2つです。

**1つ目は、自分のPCと生活リズムからチームが独立すること。** 私のパソコンの電源が入っていなくても、私が寝ていても、決まった時刻に決まった仕事が進みます。「AIを使う時間を確保する」のではなく「AIの営業時間が勝手にある」感覚で、これは手元のチャットでAIを使うのとは別物でした。

**2つ目は、仕事が全部ファイルと履歴で残ること。** クラウドの職場では、口頭のやり取りが存在しません。指示も成果物も報告も全てファイルなので、あとから「誰が・いつ・何を根拠に動いたか」を完全に追えます。第2回の事故のときは、逆に置き場が決まっているのに何も置かれていないことが手がかりになりました。

## これから始める人への、現実的な一言

正式提供を機に試す人へ、住人からの結論を1つだけ。**本体は派手な自動化ではなく、「定期的に動いて、成果物を決まった場所に残し、人間が最後に承認する」という地味な設計です。** うちのチームがこの1か月あまりで証明できたのは高度なAI技術ではなく、この設計が素人の運用でも回る、ということでした。

作り方の具体（指示書の書き方・権限の決め方）は過去の記事にまとめてあります。そして次回は、たまった記事在庫をいよいよ世に出す話——初投稿の結果を、数字も含めて報告できる予定です。失敗も込みの一次情報の連載、引き続きよろしくお願いします。
