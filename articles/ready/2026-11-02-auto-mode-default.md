# タイトル案
1. （本命）AIが承認ボタンを押させなくなる日 — 自動モード既定化と、それでも人間が押す「第3層」の話
2. 「操作ごとの承認」が標準でなくなる — 自動モード既定化を、2ヶ月線引きしてきた運用者が読む
3. 承認の担当が人間から分類器に変わる — それでもAIに渡さないボタンの話

# 本文

Claude Code の「自動モード」が、新しいセッションの**既定（デフォルト）**になります。これまでの「AIが何かする前に、人間が操作ごとに承認する」方式が標準ではなくなる、という変化です。

このニュース、「便利になる」と「怖い」のどちらで受け取るべきか、迷った人が多いと思います。私は13人のAI社員チームを運用しながら、「何をAIに任せ、何を人間に残すか」を2ヶ月かけて自分で線引きしてきた当事者です。今回はその目線で、この変化を読み解きます。

## まず、何が変わるのか（公式ページで確認した範囲）

公式の案内はこうです（確認日: 2026-11-03。時期はページ内の記述に幅があるため、「**10月下旬時点で、新規セッションの既定化が案内されている**」の粒度で書きます）。

- 対象は **Pro・Max・Ultra・Team プランの新しいセッション**（Enterprise や API 経由などは当面オプトインのまま）
- 操作ごとに人間へ承認を求める代わりに、**自動チェック（分類器）が各操作を判定**する。公式の説明では、分類器は「**取り返しがつかない操作・破壊的な操作・環境の外に向かう操作**」をブロックする設計
- ブロックが続く場合（連続3回、またはセッション中20回）は、**従来の手動承認に戻る**
- データを外部に送るような操作は「**分類器が決して承認しないよう設計された区分**」にあり、やりたければ人間が自動モードを抜けて自分で実行する
- 本番インフラへの重要な変更は、公式自身が「**引き続き自分で確認することを勧める**」と明記。「リスクを消すものではない」とも書かれている
- 戻したい人はいつでも切り替え可能（CLI は Shift+Tab、デスクトップはモード選択。管理者は設定で既定の固定や自動モードの無効化ができる）

興味深いのは公式が示した実験の数字で、1,053人のテスターを使った検証では、**危険なコマンドを人間の目は13.6%しか止められず、自動モードは89%を止めた**とされています（記事の数値）。「人間の承認」は安全装置として実はあまり機能していなかった、という身も蓋もない話です。

## 「全部自動になる」ではない — 承認の担当が変わるだけ

見出しだけ読むと「AIが承認なしで何でもやる時代」に見えますが、正確には違います。**承認という工程はなくならず、担当が人間から分類器（AIの判定役）に変わる**。そして危ない区分は分類器が止め、止めきれない領域は人間に戻ってくる——そういう多段の設計です。

実はこの形、前回のDuet記事で見た「行動の前に承認を求める」設計とも方向が同じです。公式製品は一貫して「**自動で動く範囲を広げつつ、一線の手前では止まる**」方向に進んでいます。

## うちの三層ルールと突き合わせる

うちのチームは最初から、仕事を三層に分けて運用してきました（詳しくは有料の権限設計記事・【権限設計記事のURL】）。

1. **勝手にやってよい** — 下書き・調査・整理。失敗してもやり直せる仕事
2. **やってから報告** — 保存・記録の更新。履歴が残り差し戻せる仕事
3. **人間の承認が必要** — 公開・支払い・方針の変更。外の世界に出る仕事

自動モードの分類器がやろうとしているのは、ざっくり言えば**第1層と第2層の承認を人間から引き取る**ことです。そしてうちの実感では、ここは引き取ってもらって正しい。2ヶ月の運用で、第1・2層の承認が問題になったことは一度もありません。

問題は第3層です。うちは「公開・支払い・方針変更」をどんなに成果物の質が上がっても人間に残すと決めていて、公式の設計でも、外に出る操作や取り返しのつかない操作は自動化の外側に置かれています。**既定が変わっても、「人間が押すボタン」は残る**——ここは公式とうちで結論が一致しました。

ただし、正直に両面を書きます。連載第5回で白状したとおり、うちの第3層は**安全装置であると同時に、チーム最大の詰まりどころ**でもあります（記事在庫が積み上がる一方、公開0本——止まっていたのは人間でした）。第3層を人間に残すとは、**その判断をする時間まで人間が引き受ける**ということです。自動モードがどれだけ賢くなっても、この宿題は消えません。

## うちならどう設定するか — 三層ルールからの机上整理

公式の変更履歴には、プロジェクトや過去の作業を読んで環境に合わせた自動モードの設定を手伝う `/auto-mode-setup` というガイド機能も追加されています（v2.1.304・2026-10-19、公式変更履歴で確認）。**うちのAI社員の作業環境からはこの機能を実行できなかったため**、ここでは実行記録の代わりに、うちの三層ルールをこの新しい前提に当てはめるとどうなるかを机上で整理します。

- **第1層（下書き・調査）**: 自動モードに全面的に任せる。承認で止める価値がそもそもない
- **第2層（保存・記録）**: 任せる。ただし「履歴に残る場所でだけ作業する」という前提は崩さない——差し戻せることが、承認を省く条件なので
- **第3層（公開・支払い・ルール変更）**: 自動モードの既定化とは無関係に、**指示書の側で「AIはやらない」と書き続ける**。分類器が止めてくれるかどうかに頼らず、そもそも任せない仕事として定義しておく

3つ目がうちの結論の核です。分類器は「危ない操作を止める」仕組みですが、**何が自分にとっての一線かを決めるのは、相変わらず運用者の仕事**です。

## まとめ: 既定値は変わる。自分で引いた線は無駄にならない

今回の変化をひとことで言えば、「承認の既定値が、人間から分類器に変わる」です。便利になるのは間違いありません。危ないのは、既定値に任せきりにして**自分の一線を一度も考えないまま運用を始める**ことのほうだと思います。

うちは2ヶ月、承認ボタンを押しながら「これはAIでよかった」「これは人間で正解だった」を体験で仕分けてきました。その線引き表は既定値がどう変わっても持ち越せます。何をどこまで任せるかの実物の線引き表とチェックリストは、有料記事（【権限設計記事のURL】）にまとめてあります。あわせてどうぞ。
