# タイトル案
1. （本命）「承認疲れ」で形だけのOKを押す前に — 人間の承認を「はい/いいえ」の数問まで減らした、うちの実データ
2. AIへの承認、全部読んでいますか — 97%が「はい」で流れる確認を、数問まで絞った話
3. 全部確認すると形だけになり、全部任せると事故る — 承認を「減らす」のではなく「種類で絞る」設計

# 本文

AIに仕事を任せ始めると、最初はこう考えます。「何をするにも、必ず私の確認を通すこと」。安全のためには当然の構えです。

ところが数週間もすると、別の問題が顔を出します。確認が多すぎて、**中身を読まずにOKを押している自分**に気づくのです。「承認疲れ」と呼ばれる状態で、全部確認すると形だけになり、かといって全部任せると事故る——この二重の罠が、いまAI活用の論点になりつつあります。

これは印象論ではありません。Anthropic が公式に出しているデータ（確認日: 2026-11-10）によると、Claude Code の利用者は**許可の確認の97%を承認**しており、手動の確認は習慣的になりうると公式自身が書いています。さらに実験では、危険なコマンドを人間が止められた割合は**セッションの序盤で約17%、それまでの確認が50回以上になったあとは約5%まで下がった**とされています。押す回数が増えるほど、確認は効かなくなる——「承認疲れ」は、数字で測れる現象でした。

私は13人のAI社員チームを2ヶ月半運用してきた非エンジニアです。今回は、うちが人間の承認を「はい/いいえで答えられる数問」まで減らした設計と、**オーナー（私）が実際に何回答えたかの実数**を公開します。

## うちの設計 — 承認を「減らす」のではなく「種類で絞る」

うちのチームは最初から、仕事を三つの層に分けています（詳しい振り分け表は有料の権限設計記事・【権限設計記事のURL】にあります）。

1. **勝手にやってよい** — 下書き・調査・整理。失敗してもやり直せる仕事
2. **やってから報告** — 保存・記録の更新。履歴が残り、差し戻せる仕事
3. **人間が押す** — 公開・支払い・方針の変更。外の世界に出る仕事

ポイントは、承認の回数を我慢して減らすのではなく、**第1層・第2層の承認を最初からなくし、第3層だけに人間を置く**ことです。97%が「はい」で流れる確認を1,000回押すより、本当に人間が決めるべき数問にだけ向き合うほうが、安全装置として機能する——そういう割り切りです。

## 実データ: 人間は実際に何回押したか

うちには、各記事や成果物に残った確認事項を「はい/いいえか一言で答えられる質問」に変換してオーナーに届ける係（仕上げ担当）がいます。その質問シートの反映記録に残っている範囲で数えると——

- **約5週間で、オーナーが実際に答えた質問は16問**でした
- 回答のほとんどは一言です。記録に残っている実例: 「はい」「このまま」「残す」「新しい順でOK」「なおしました」
- 無回答のまま期限が来た質問は**2問**あり、どちらも事前に決めてあった「無回答時のデフォルト（安全側）」で処理されました
- いま回答待ちの質問は**4問**です

13人が毎日動いているチームで、人間の判断は週に3〜4問。1問あたりの回答は一言。これが、承認を「種類で絞った」結果の実物の数字です（数えられる記録の範囲のみで、推計は入れていません）。

## それでも起きたこと — 承認疲れの反対側には「承認待ち渋滞」がある

ここまでだと成功譚ですが、正直に裏面も書きます。承認を数問まで絞っても、**人間が答えない期間**は発生します。

うちの実例でいえば、公開してよい記事の在庫が21本まで積み上がる一方、**投稿は50日以上ゼロ**のままです。記事に出典つきの1行を足すかどうかという「はい/いいえ」1問が、**2週間以上回答待ち**になったこともあります。連載の第5回で白状したとおり、止まっていたのはAIではなく人間でした。

つまり承認疲れの反対側には「承認待ち渋滞」があります。承認を人間に残すとは、**その判断をする時間まで人間が引き受ける**ということで、問題は「何問にするか」から「残した数問に、人間がちゃんと向き合えるか」に移るだけなのです。

【あなたの体験をここに: 「はい/いいえだけ答えればいい」運用への率直な感想。答えずに溜めてしまった時期があれば、その正直な理由（任意・1〜2文。なければこの一文は削除してください）】

## 設計のコツ2つ

うちの運用から、持ち帰れそうなコツを2つだけ。

**① 質問を「はい/いいえ」に変換する係を置く。** AIからの確認は、放っておくと「どうしましょうか？」という開いた質問で届きます。うちは仕上げ担当という係を1人置いて、すべての確認を「はい/いいえか一言」+「無回答ならこう処理します」の形に変換させています。人間の負荷は、質問の数より**質問の形**で決まります。

**② 無回答時のデフォルトを安全側に決めておく。** うちの質問には必ず「答えがなければ、該当の一文を削除」「足さない＝今のまま」といったデフォルトが付いています。事実を創作する方向のデフォルトは禁止。だから溜めても事故にはならず、「もったいない」止まりで済みます。

## まとめ

- 全部確認は形骸化します。公式データでは確認の97%が承認され、止める力はセッション中に17%→5%まで落ちます
- うちは承認を「減らす」のではなく「種類で絞り」、人間の判断を約5週間で16問・ほぼ一言回答まで圧縮しました
- それでも「承認待ち渋滞」は起きます。残した数問に向き合う時間までが、人間の仕事です

何を第1層に落とし、何を第3層に残すか——うちの実際の振り分け表と、2ヶ月半で起きた事故の記録は、有料の権限設計記事（【権限設計記事のURL】）にまとめてあります。あわせてどうぞ。
