# note事業部

note記事の制作・公開・SNS集客をAI社員（Routine）で運用する事業部のフォルダ。

## メンバーと稼働スケジュール（JST）

| 役割 | 稼働 | 仕事 |
|---|---|---|
| ライター | 火・木 8:00 | `drafts/` に記事ドラフトを1本執筆し、`claude/writer-draft-YYYYMMDD` ブランチにプッシュ |
| 編集長 | 月 8:00 | `drafts/` の記事をレビュー・編集し、`published/` へ移動。`claude/editor-review-YYYYMMDD` ブランチにプッシュ |
| リサーチ | （未稼働） | ネタ候補・参考資料を `research/` にストックする予定 |
| SNS担当 | （未稼働） | `published/` の記事の告知文を `sns/` に作成する予定 |

## フォルダ構成

- `drafts/` — ライターが書いた記事ドラフト（`YYYY-MM-DD-スラッグ.md`、front matter付き）
- `published/` — 編集長の編集を終えた公開可能な記事
- `research/` — ネタ帳・参考資料（リサーチ担当の作業場所）
- `sns/` — SNS告知文の下書き（記事URLは `{URL}` プレースホルダ）
- `編集方針.md` — テーマ・文体・想定読者などの編集方針。全メンバーがこれに従う

## 運用フロー

1. ライターが `drafts/` にドラフトを書く（火・木）
2. 編集長がレビューして `published/` へ移す（月）
3. 人間（事業部長）が `published/` の記事をnoteに投稿する
4. （将来）SNS担当が告知文を作り、人間がURLを差し込んで投稿する

記事のnoteへの投稿とSNSへの実投稿は自動化されていない。人間の作業として残っている。
