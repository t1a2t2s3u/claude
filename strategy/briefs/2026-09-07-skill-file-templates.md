# ブリーフ: AI社員の「雇用契約書」＝スキル定義ファイルの書き方（うちのチーム全員分の実物付き）
- 状態: 執筆済み
- 種別: 有料（想定価格帯: 500〜980円）
- 想定読者: Claude Code で AI社員・AIエージェントを作ってみたいが、
  「スキル定義（指示書）に何をどこまで書けばいいのか」で手が止まって
  いる人。エンジニアではなく、日本語で指示を書きたい層
- この記事が買われる理由: 解説記事は「スキルを書けば動く」と言うだけで、
  **現に運用されているスキル定義の実物**はほぼ公開されていない
  （設計図公開系の記事はエンジニア向けのコード中心）。この記事は
  実際に毎週動いているチーム7人分の SKILL.md 全文と、それを一般化した
  コピペ用テンプレートを渡す。読者はその日のうちに自分の「AI社員」の
  指示書を書き上げられる＝時間の節約という実用価値
- 構成案:
  - 【無料部分】
    1. スキル定義ファイルとは何か —「AI社員の雇用契約書」という比喩で、
       役割・手順・してはいけないことを書く場所だと説明
    2. なぜ指示書の書き方で AI社員の働きが決まるのか（うちの実例:
       同じ Claude でも秘書と編集長で全く違う動きをする）
    3. 書き方の3原則の紹介（詳細と実物は有料部分へ、と線引きを明示）
  - 【有料部分】
    4. 書き方の3原則の詳細 — ①役割と管理対象を1行で断言する
       ②定期稼働時の手順を番号付きで書く ③「してはいけないこと」を
       必ず設ける（うちの実ファイルでの具体例つき）
    5. 実物公開: 秘書・編集長・リサーチャー・ライター・校閲・SNS担当・
       アナリストの SKILL.md 全文（このリポジトリの実ファイルをそのまま。
       オフィスボード報告など読者環境で再現できない箇所には注記を付ける）
    6. コピペ用の汎用テンプレート（役割名・管理対象・定期稼働手順・
       禁止事項の穴埋め式）＋自分の業務に当てはめる手順
    7. よくある失敗と直し方（例: 手順が曖昧だと毎回違う動きをする、
       禁止事項がないと越権する — 実際に観察した範囲で）
- 有料部分に入れる実用価値: 運用実績のあるスキル定義7本の全文、
  穴埋め式テンプレート、書き方チェックリスト
- ユーザー記入ポイント:
  - スキル定義を書き直して挙動が変わった実体験があれば1つ
    （なければライターはこの節を削って構成すること。捏造不可）
- 備考: SKILL.md の引用はこのリポジトリの実ファイルからそのまま行う
  （捏造の余地なし）。ブランチ名・セッションIDなど読者に無関係な
  内部情報は伏せる。既刊の有料手順書（2026-08-30-ai-secretary-howto）
  とは「秘書を1人作る手順」vs「チーム全員分の指示書の書き方」で
  差別化し、本文中で相互リンクさせる
