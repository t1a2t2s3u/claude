# ブリーフ: 1ヶ月半書き足してきたAI社員の指示書を、AIに点検させてみる — 「指示書の健康診断」機能の実録
- 状態: 執筆済み
- 種別: 無料（集客・新機能便乗＋運用実物公開）
- 想定読者: AI社員・エージェントの指示書（CLAUDE.md・スキル）を
  書き足し続けて「古い記述や矛盾が混ざっていそう」と感じ始めた運用者。
  Claude Code の指示書点検機能（/doctor prompt-audit）の実例を探す人
- この記事が読まれる理由: 機能紹介は解説ブログが既に書いているが、
  **「1ヶ月半、13人分の指示書を書き足してきた実物のリポジトリ」に
  かけた結果**は、うちにしか出せない。うちは実際に監査役から
  「指示書と実態のずれ」を何度も指摘されてきた（記録あり）ので、
  「指示書は腐る」という問題意識を実体験で語れる
- 構成案:
  1. 問題提起: 指示書は書いた瞬間から古くなる — うちで実際にあった
     「指示書と実態のずれ」の実例を1〜2件（audit/ や各スキルの改訂
     履歴から、確認できる範囲で。本業側の事例は使わない）
  2. ニュース: Claude Code に指示書の点検機能が入った
     （**執筆前に公式変更履歴（code.claude.com/docs）で機能名・挙動を
     必ず確認**。解説ブログの記述と食い違う場合は公式に従う）
  3. 実際にかけてみた — うちの指示書一式を点検した結果を正直に公開
     （何件・どんな種類の指摘が出たか。恥ずかしい指摘ほど価値がある）。
     **ライターの環境で実行できない場合は、この節を「点検の観点を
     手動でなぞってみた」に差し替え**（指示書の古い参照・矛盾を自分で
     探した結果を書く。「機能を実行した」とは書かない）
  4. 見つかったものをどう直すか — 直す判断は人間（オーナー承認系の
     ルール）とAI（事実のずれ）で分かれる、といううちの運用
  5. まとめ: 指示書のメンテナンスは「AI社員の健康診断」。書きっぱなしに
     しない仕組みごと真似してほしい
  6. 関連記事への誘導（雇用契約書＝スキル定義の有料記事）
- ユーザー記入ポイント:
  - なし（リポジトリと公式ドキュメントで完結する想定）
- 備考: 機能の名称・挙動・利用条件は公式変更履歴で裏が取れた範囲のみ。
  実行していないことを実行したと書かない（構成案3の差し替え規定を厳守）。
  点検結果の公開は note編集部・管理部関連に限定し、本業（seo/）の
  指示書の内容には触れない（2026-09-20 オーナー決定）。
  ブランチ名・セッションID等の内部情報は伏せる
