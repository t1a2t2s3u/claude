# ブリーフ: AIに仕事を任せるなら「作る係」と「疑う係」を分ける — AI社員でも採用選考でも同じだった
- 状態: 未着手
- 種別: 無料（集客・設計パターンの横展開。AI社員界隈の外の読者を取りに行く）
- 想定読者: AI社員運用者に限らず、**仕事のどこかにAIを入れ始めた人全般**
  （書類選考・経理チェック・文書作成など）。「AIの出力をそのまま
  使っていいのか」に不安がある層
- この記事が読まれる理由: 「点検役のAIを別に置く」という設計が、
  AI社員界隈の外（採用の書類選考など）でも語られ始めた。
  この記事は分野を問わない**設計パターン**として整理した上で、
  2ヶ月半の実運用記録（点検役が実際に捕まえた誤り・点検役自身が
  間違えた記録まで）を証拠として出せる — 理屈だけの解説と違い、
  「実際にやるとどうなるか」まで含めて1本で読める
- 構成案:
  1. 広がっている考え方 — 「作るAIと点検するAIを分ける」が、
     AIチーム運用の外でも推奨され始めた（勉強会資料など出典付きで
     1段落。分野例: 採用・文書チェック）
  2. なぜ分けると効くのか — 同じAIに自己点検させると同じ癖で見逃す。
     別の役割・別のタイミング・別の指示書で見ると捕まる、という原理を
     非エンジニア向けの言葉で
  3. うちでの実績 — 点検役（監査役）が2ヶ月半で実際に捕まえたもの
     （事実誤り・誇張・古い情報の残留。audit/ の記録から実例を
     2〜3件、note編集部関連に限定）
  4. 分ける設計の3条件 — うちの運用から一般化:
     ①点検役は直さない（指摘だけ。直すのは作る係か人間）
     ②点検の結果もファイルに残す ③点検役への反論経路を作る
     （点検役自身が間違えた実例と訂正の話 = 運用日記06へリンク）
  5. 自分の仕事に当てはめるなら — 採用・経理・記事作成を例に、
     「作る係・疑う係・決める人間」の3役を紙に書き出すだけの
     ミニワーク（一般論の範囲で。各分野の専門的助言はしない）
  6. 関連誘導（見張り役AI記事・運用日記03/06・有料の権限設計）
